# yomi relay --channel wechat --experimental（实验功能）

**仅限个人使用**：relay 只转发你本人和你自己的微信 ClawBot 之间的消息，不要拿来给别人提供服务。
**实验功能**：微信 ClawBot（iLink）不是给第三方客户端的官方接口，对这类客户端的使用条款还不明确；不加 `--experimental` 不会启动。

通用的运行方式、聊天里的命令、钱和隐私见 [docs/relay.md](relay.md)，本文只写微信自己的部分。

## 微信 ClawBot 是什么

ClawBot 是微信里的一个插件：扫码绑定后，你的微信号和一个 bot 之间有一个一对一的会话，绑定它的程序通过腾讯的 iLink 接口收发这个会话里的消息。腾讯在 GitHub 上开源了给 OpenClaw 用的接入插件（[Tencent/openclaw-weixin](https://github.com/Tencent/openclaw-weixin)，MIT 许可）和它的[协议文档](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol.md)。yomi-cli 按这份文档（插件 2.4.10 版）自己实现了客户端，没有使用插件本身。

- 不需要注册开发者，也不需要公网地址：relay 只发起出站 HTTPS 请求，用长轮询收消息。
- relay 向服务器如实声明自己：`channel_version` 为 `2.4.10/yomi-cli-<版本>`，`bot_agent` 为 `yomi-cli/<版本>`，不冒充 OpenClaw。
- 只有私聊：群消息一律忽略。

## 为什么是实验功能

- **第三方客户端能不能接入，没有明确说法。** 协议文档面向“实现或对接兼容后端的开发者”，同时说明客户端的行为不构成完整的服务端约定；没有一句话明确允许第三方客户端接入。
- **条款要你自己看。** 在微信官方网站上没有找到这个产品的说明和条款原文。**使用前请在手机微信里打开 ClawBot，阅读它的条款**；如果条款不允许这样使用，就不要用。
- **限制没有公开。** 发送频率、回复时限、每条消息能回几条，官方都没有写。下文的数字是 relay 的保守假设，在真机上核实之前都可能调整。
- **绑定流程会变。** 协议文档的发布说明写着：将来绑定时可能要输入手机上显示的数字（PIN），绑定别人的 bot 要先做实名授权；目前两项默认关闭，没有定切换日期。relay 已支持输入数字，不支持绑定别人的 bot。
- 腾讯可以随时修改或关闭这个接口。账号可能受到的影响由你自己判断。
- 在生产环境，服务端也要为微信通道明确开放后 relay 才会转发（见 [docs/relay.md](relay.md)）。

## 仅限个人使用

- 只转发你本人发给自己 ClawBot 的消息；别人发来的消息不转、不扣费。
- 对话会经过腾讯的服务器，由腾讯按它的隐私政策处理；在 Yomi 里删除会话，不会删掉微信里的消息。
- 和 AI 角色的拟人化互动在中国大陆受《人工智能拟人化互动服务管理暂行办法》（2026-07-15 施行）约束。个人使用以外的任何用途，都需要先有法律意见。

## 准备与登录

1. 先 `yomi login`（relay 使用 CLI 自己的 Yomi 会话）。
2. 手机上准备好微信。协议文档写明扫码的微信号需要**已开通微信支付实名**；需要的微信版本和 ClawBot 的入口位置只见于媒体报道（例如 iOS 8.0.70 起），以你手机上的微信为准。
3. 在电脑的终端里运行：

   ```sh
   yomi relay --channel wechat --experimental --login
   ```

   - 先显示上面这些说明，输入 `yes` 才继续。
   - 终端里会画出一个二维码，用手机微信扫码，并在手机上确认。
   - 如果手机上显示了一组数字，终端会提示你把它输进去。
   - 二维码过期会自动换一个，一次登录最多 3 个；整个登录最多 8 分钟。按 Ctrl+C 可以随时取消。

**扫码的人就是主人。** 主人按 Yomi 的正常规则花这个账号的钻石（和在 App 里一样）；除非用 `--max-spend` 启动 relay，否则没有上限。所以二维码要当密码看，想限制花费就加 `--max-spend`：

- 不要在共享屏幕、录屏或直播里显示二维码。
- 默认只画二维码，不打印它的链接；加 `--qr-link` 才打印（终端太窄画不下时也会打印）。
- 登录结束时（成功、失败或 Ctrl+C），屏幕上的二维码和链接会被擦掉（输出到终端时）。终端窗口比二维码还矮时，已经滚出屏幕的部分擦不掉，会留在滚动记录里：把窗口拉高再登录，或登录后清空滚动记录。

登录之后：

- 登录凭证（`bot_token` 等）只保存在系统钥匙串里；没有钥匙串时要加 `--allow-file-store`，才会写进 0600 的本地文件。它不接受命令行参数和环境变量，也不会出现在日志里；二维码的内容同样不记录。
- 一个微信号可以连接多个 ClawBot：每扫码连接一个新的 ClawBot，就添加一个 bot（`--login --character <ID>`），各自有自己的状态和主人记录。登录过期时用 `yomi relay --bot <名字> --login` 只重新登录这一个，二维码请求只带上这一个的登录。
- 同一个微信号重新扫码登录，主人、预算、还没核对的花费和记录都保留（即使 bot 换了 ID）。换一个微信号扫码就是换了主人：旧主人和他的预算、记录会被清除（终端里会提示），新主人从头开始，没有预算（不设上限，按 Yomi 的正常规则扣费，`--max-spend` 仍然有效）。
- 终端里有 relay 在运行时不能 `--login`：先停止它（Ctrl+C）；后台服务在运行时，命令会先停止它，登录完再重新启动。
- 微信说这个 ClawBot“已经绑定”时：重新登录一个 bot，就保留它原来的登录；添加新 bot 时，说明它已经是这台电脑上的某个 bot，什么都不保存（用 `yomi relay --list` 看名字，再 `--bot <名字> --login`）；本机没有任何登录（例如 `--forget` 之后、换了电脑）就要先在手机微信里解除 ClawBot 的绑定，再 `--login`。

## 运行

```sh
yomi relay --channel wechat --experimental --character 7300000000000009001 --max-spend 100
```

启动时终端会提示“仅限个人使用”和“实验功能”。之后直接在微信里和 ClawBot 聊天即可；`/help` 列出命令（微信里没有命令菜单）。

微信的 bot 不能先开口，所以绑定后的介绍（AI 提示、角色的封面图、简介、开场白或最近一条回复，见 [docs/relay.md](relay.md#运行与配对)）在 `--login` 之后你发来的第一条消息时发出，然后才是对这条消息的回复，前后大约多几秒。同一个微信号重新登录、relay 重启都不再发；换一个微信号扫码登录会发。

后台服务：`--install-service`（macOS 的 LaunchAgent 是 `io.yomichat.yomi-cli.relay.wechat-<环境>`，Linux 是 `yomi-relay-wechat-<环境>.service`），服务的启动参数里自带 `--experimental`。安装前要先登录过；同一个 Yomi 账号和环境只能装一个 relay 服务。

## 能做什么，不能做什么

| 能力         | 微信 ClawBot                                                                   |
| ------------ | ------------------------------------------------------------------------------ |
| 回复怎样显示 | 先显示“正在输入”，整条回复好了再发出；长回复分成几条，每条最多 2000 字（假设） |
| 停止当前回复 | 发 `/stop`（没有“停止”按钮）                                                   |
| 需要确认时   | 没有按钮：消息里有一次性代码和带编号的选项，回复“代码 序号”，例如 `K7Q2 1`     |
| 引用某条消息 | 不支持：`/report` 和 `/image` 针对最近一条回复                                 |
| 图片         | `/image` 的图片加密上传后发回聊天，前面一条是说明文字                          |
| 你发的内容   | 只转发文字；语音、图片、文件会收到“目前只支持文字消息”                         |
| 群聊         | 不支持，群消息被忽略                                                           |
| 消息格式     | 纯文本；旁白放在括号里，群聊角色的台词前面写名字                               |

为什么不边写边显示：微信的消息发出后不能修改，而审核过的段落在回复完成前还可能变化，所以 relay 等回复完整了才发，期间显示“正在输入”。

## 回复时限与“你不在时的消息”

微信的 bot 只能回复你发来的消息：每条消息带一个回复凭证（`context_token`），回复要带上它。relay 的假设是：每条消息 23 小时内可以回复，最多回 10 条，相邻两条至少间隔 1 秒（官方没有公布，可能调整）。登录后第一条消息先发的介绍也算在这 10 条里（通常 4 条），超出的部分按下面的规则排队。如果微信拒绝了对一条较早消息的回复，relay 就不再用那条消息。

不在这个时限内的内容（服务端的提醒、迟到的图片结果、Yomi 登录状态的变化等），不会丢，而是排队：等你下一条消息到达时，relay 先发一条“你不在时的消息（N 条）”，再处理你的新消息。队列最多 20 条，超过 24 小时的不再发。排队的图片在 relay 没重启时会一起发出；重启后只留一句“图片已经在 Yomi 对话里”。

relay 没在运行时你发给 ClawBot 的消息，按协议会在重新连上后收到（还没在真机上核实）；其中超过 10 分钟的不会转给角色，也不扣费，只对最新的一条回复“这条消息是 relay 离线时发的”。

## 登录失效

- 微信返回 -14（登录失效）时，relay 和官方插件一样暂停 1 小时，然后再试。暂停期间 relay 不收消息；暂停结束后，这期间你发的消息里超过 10 分钟的不转发、不扣费（只对最新一条回复离线提示），最近 10 分钟内的照常转发。暂停前已经在写的回复不会发出，下次你发消息时会提醒你去 Yomi App 或网页查看。
- 连续 3 次 -14，或微信连续 3 次拒绝登录凭证，relay 会停止并提示重新登录这个 bot：`yomi relay --bot <名字> --login`（只有一个微信 bot 时也可以用 `yomi relay --channel wechat --experimental --login`）；后台服务也会停下，不会反复重启。重新登录后自动从头计数。

## 解除绑定与删除

```sh
yomi relay --channel wechat --forget
```

- 删除本机保存的微信登录、这个通道的记录（主人、预算、队列、游标）和它的后台服务；Telegram、QQ 的不受影响。`--forget` 不需要 `--experimental`。微信有多个 bot 时，用 `yomi relay --forget --bot <名字>` 一个一个删除（`--forget --all` 会删除这台电脑上所有通道的全部 bot，包括 Telegram 和 QQ 的，以及它们的后台服务和花费记录）。
- 然后在手机微信里解除 ClawBot 的绑定（在 ClawBot 插件的设置里，具体位置以你的微信为准）。只删除本机的登录不会让那个 `bot_token` 在微信那边失效；要让它失效，应在手机上解除绑定（解除后的具体效果还没在真机上核实）。
- 怀疑二维码或登录被别人拿到时：立刻在手机微信里解除绑定，再 `--forget`，需要时重新 `--login`。

## 本机保存什么

`~/.config/yomi-cli/relay/` 下这个微信号对应的一个 0600 文件：你的 iLink 用户 ID、是否已经发过介绍（用户 ID 的哈希和当时的角色）、收消息的游标、最近 200 条收到的消息的 ID（重启后不重复转发）、最新一条消息的回复凭证和已回复条数（没有钥匙串里的 `bot_token` 就没有用）、排队的提醒、还没回答的确认代码，以及和其他通道相同的预算与记录。日志只记录状态，不记录消息内容、令牌、回复凭证和二维码。

## 需要在真机上核实的事

relay 现在按下面的假设运行，核实前都可能调整：回复时限和条数（23 小时、10 条）；收到的消息里 `from_user_id` 是否就是登录时的 `ilink_user_id`（不是的话 relay 认不出主人）；“正在输入”能显示多久；单条消息的长度上限；重新登录是否换 bot ID、旧的登录是否立即失效；不带回复凭证的消息能否送达；relay 停着时发的消息重新连上后是否还能收到；手机上解除绑定后旧的登录是否立即失效；服务器是否接受 relay 声明的协议版本 2.4.10。
