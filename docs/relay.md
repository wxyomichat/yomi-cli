# yomi relay（实验）

把你**本人**在私聊里发给自己 bot 的消息，转给一个已发布的 Yomi 角色，并把角色的回复发回这个私聊。bot 是你自己的，它的凭证只存在这台电脑的系统钥匙串里；relay 只发起出站连接（聊天平台的长轮询或长连接、Yomi 长连接），不在本机开端口。

| 通道                  | 怎样选择                                | 说明                   | 准备、配对、能力与限制                  |
| --------------------- | --------------------------------------- | ---------------------- | --------------------------------------- |
| Telegram              | `--channel telegram`（或 `--telegram`） | 实验                   | 本文的 [Telegram](#telegram) 一节       |
| QQ                    | `--channel qq`                          | 仅限个人使用           | [docs/relay-qq.md](relay-qq.md)         |
| 微信 ClawBot（iLink） | `--channel wechat --experimental`       | 实验功能，仅限个人使用 | [docs/relay-wechat.md](relay-wechat.md) |

下文的运行方式、聊天里的命令、钱、隐私和后台服务对所有通道相同；各通道自己的部分（怎样拿到 bot、怎样配对、能不能流式显示、离线时的消息）在各自的文档里。

服务端通过 `relay/get_policy` 声明它已经支持的能力（只用免费额度、花费上限、合规提示注入等），请求里带着通道名。没有声明的能力，relay 不会假定服务端支持：只用免费额度时一条也不发，设了上限（预算或 `--max-spend`）时要能读到价格才发，AI 提示由 relay 自己显示；不设上限（默认）时，这些都不影响转发。在生产环境，QQ 和微信只在服务端明确为这个通道返回了策略时才转发；否则每条消息都只会收到「服务端已关闭」的答复，不转发、不扣费，服务端开放后自动恢复。测试环境和自定义地址只提示一句，照常运行。

## 运行与配对

先 `yomi login`（relay 使用 CLI 自己的 Yomi 会话），保存好通道的凭证（见各通道的文档），然后：

```sh
yomi relay --channel telegram --character 7300000000000009001
```

- **每个 bot 固定一个角色**：运行时的 `--character` 只给还没有角色的 bot 绑定角色，已经绑定的 bot 会提示并忽略它。要换角色，运行 `yomi relay --bot <名字> --character <ID>`（名字见 `yomi relay --list`）：后台服务在运行时会先停止它、换绑后再重新启动；终端里有 relay 在运行时会被拒绝，先停止它（见下文）。一个角色只能绑一个 bot。聊天里的 `/character` 只会回复当前角色和换绑的命令，角色下架或暂时不可用时也会回复换绑的命令；还没有角色的 bot 对每条消息只回复「在电脑上绑定角色」，不转发、不扣费。
- 只服务配对过的本人：Telegram 和 QQ 在终端里显示一次性的配对码（15 分钟内有效、只能用一次、同一个人错 5 次作废），在聊天里发给 bot；微信是扫码登录的人。之后别人发来的消息不会转给 Yomi，也不会扣费。要换人：`--pair`（Telegram、QQ）或重新 `--login`（微信）。
- relay 离线时你发的消息（超过 10 分钟）不会补转，以免意外扣费。
- **绑定后的介绍**：bot 绑定到新主人后，relay 先发一次介绍：AI 提示、角色的封面图、角色简介，然后是开场白；你已经在 App 或网页上和这个角色聊过时，改发角色在那段对话里的最近一条回复。Telegram 和 QQ 在配对成功的消息之后发；微信不能主动发消息，所以在 `--login` 之后你发来的第一条消息时，先发介绍，再回复那条消息。bot 换绑到另一个角色后，在回复你的下一条消息之前，用新角色再发一次介绍。这个角色上一次是给别人用的（例如另一个 bot 的主人，或这个 bot 之前的主人），只发开场白，不发那段对话里的回复。服务端还没确认这个通道、或 relay 暂停时，介绍先不发，等恢复后你的下一条消息时再发。
  - 免费：只读角色资料和聊天记录，不发消息给角色，不扣费。封面在这台电脑上下载后上传给聊天平台，下载或上传失败时只发文字；读不到角色资料时，等你下一条消息再发。
  - 每个主人只发一次，bot 换绑到另一个角色后再发一次（换回之前的角色也会再发）：同一个人重新配对或重新登录、relay 重启（包括后台服务）都不再发；换了一个人（另一个用户 ID）、或 bot 换绑了角色，会发。从旧版本升级时，当前的主人算已经发过。`--forget` 删除记录后，下次配对会重新发。
- 凭证不接受命令行参数和环境变量（会出现在 `ps`、shell 历史、子进程里）：在终端里输入（不显示），或用 `--token-stdin` 从标准输入读。没有系统钥匙串（Linux 没有 Secret Service 时）relay 默认拒绝启动，确认接受明文 0600 文件时才加 `--allow-file-store`。
- QQ 和微信启动时会提示「仅限个人使用」；微信还会提示它是实验功能，不加 `--experimental` 不启动。

同一个 Yomi 账号和环境，本机同时只能运行一个 relay，不论通道（两个 Telegram bot 也一样）：几个 relay 会共用 Yomi 长连接的设备 ID，互相取走对方的离线消息，按余额差额核对的花费会算进对方花的钻石，`--max-spend` 本机上限也会被每个 relay 各花一遍。所以第二个 relay 会被拒绝，并说明正在运行的是哪个通道、哪个 bot、哪个进程；已经装了另一个通道的后台服务时，要先用那个通道的 `--uninstall-service` 删除它，才能装新的。

改动 bot（添加、重新设置凭证、换绑角色、删除）时不能有 relay 在运行，同一时间也只能有一个改动：后台服务正在运行时，命令会先停止它，改完（包括微信扫码）再重新启动它，并在终端里说明，这期间其他 bot 也会离线；终端里有 relay 在运行时，命令会被拒绝，先停止它（Ctrl+C）。后台服务运行时用 `--pair` 配对，会先停止服务，在这个终端里显示配对码，配对完成（或按 Ctrl+C）后重新启动服务；这次配对按后台服务的花费上限运行，不会重新计算累计花费（`--pair` 加了不同的 `--max-spend` 或 `--reset-spend` 会被拒绝，要改上限就重新 `--install-service`）。后台服务停止期间按 Ctrl+C 或关掉终端，命令也会先重新启动服务再退出。新添加的 Telegram、QQ bot 用 `yomi relay --bot <名字> --pair` 配对；后台服务在运行时，`yomi relay --channel <通道>` 遇到这个通道还没有 bot，只添加 bot，不在终端里运行。

## 聊天里的命令

| 命令                              | 作用                                                                                                         |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 直接发文字                        | 转给当前角色，把回复发回来（Telegram 是可以点「停止」的「思考中」草稿，其他通道见各自的文档）                |
| `/character`                      | 显示 bot 固定的角色，以及在电脑上换绑的命令（聊天里不能换角色）                                              |
| `/price`                          | 每条回复的价格（`reply_cost_diamonds`，仅供参考）、余额、预算或累计花费                                      |
| `/budget`                         | 查看上限和通过 relay 累计花了多少钻石                                                                        |
| `/budget 100`                     | 设置可选的钻石上限（要确认）                                                                                 |
| `/budget none`                    | 不设上限，按 Yomi 的正常规则扣费（默认；从预算或只用免费额度改过来时要确认）                                 |
| `/budget off`                     | 只用免费额度，不花钻石                                                                                       |
| `/report`                         | 举报最近一条回复（Telegram 也可以回复某条消息再发 `/report`），也可以举报角色                                |
| `/image`                          | 根据最近一条回复生成一张图片（Telegram 里回复角色的某条消息再发，则根据那一条），图片发回聊天                |
| `/image resume` / `/image forget` | 用同一个请求号继续上一次没有结果的生图（不会重复扣费）/ 放弃追踪一个结果未知的请求；已被服务端受理的不能放弃 |
| `/stop`                           | 停止转发当前回复，或停止等待图片。服务端没有中止生成的接口，**照常扣费**                                     |

需要你确认的地方（`/budget 100`、`/budget none`、`/report` 的选项）：Telegram 点按钮；QQ 和微信没有按钮，消息里给出一个一次性代码和带编号的选项，回复「代码 序号」（例如 `K7Q2 1`）选择，10 分钟内有效，重启后旧代码只会得到「已过期」。

## 钱

- **默认不设上限**：和在 App 里一样，按 Yomi 的正常规则扣费（先用免费额度，用完后按每条回复的价格扣钻石），不需要先设预算。聊天里不会每条都报花费；终端日志记录每次核对出的花费，`/budget` 和 `/price` 显示通过 relay 累计花了多少。
- 钻石不足时，服务端拒绝这条消息，relay 在聊天里提示「钻石不足，请在 Yomi App 或网页充值后再发」，**继续运行**：不暂停、不用重启，充值后直接发下一条。生图同样。提示里不附链接（Telegram 规定 bot 里的数字商品只能用 Stars 购买；其他通道同样处理）。
- 上限是**可选**的，有两种，设了就照原来的规则执行：
  - 电脑上用 `--max-spend <钻石>` 设本机上限。它是**累计**的：聊天里怎么重设预算都不会重置它，只有在电脑上改 `--max-spend` 的值（包括去掉它）或加 `--reset-spend` 才重新计算。设了它，即使聊天账号被别人拿到，也花不过本机上限。`--max-spend 0` 表示只用免费额度。
  - 聊天里用 `/budget N`（N 不超过本机剩余额度）并确认。重新配对、或电脑上换了 Yomi 账号，预算都会作废，回到不设上限。`/budget none` 去掉预算（确认后生效），`/budget off` 改为只用免费额度。
  - 上限用完就不再发送，不会自动续，也不会自动重试发送；提示会说是预算还是本机上限用完了，以及怎样继续。预算用完时这个 bot 暂停，要主人在聊天里重新设预算；本机上限用完时不记暂停，每次发送前重新判断，在电脑上提高或去掉 `--max-spend`（或加 `--reset-spend`）重新启动后就继续，不用改预算。
- 每条消息都核对花费：服务端报了扣费就直接计入；否则发送前后各读一次余额，按差额计入（同时在 App 里花的钻石也会算进来，偏保守）。另一个 bot 的发送或还没结算的图片可能落在同一段差额里时，这条回复最多按它的报价计入。一条消息的花费还没核对清楚（网络中断、relay 被停止、登录失效），会记在本机，重启后也不会丢。
  - 设了上限时核对是严格的：读不到余额、或上一条的花费还没核对清楚，就不发送；读不到每条回复的价格时也不发送（价格未知不代表免费）。回复期间余额反而增加时，按报价计入。第一次在预算下给某个角色付费发送前，会先显示单价和余额。
  - 不设上限时核对只是记账，不会挡住消息：读不到余额也照发，花费等下次能读到余额时一起核对（两条一起量，不会重复计入，也不会漏掉）；实在量不出来的会计数，`/budget` 会说明累计花费可能偏少（图片不在此列：扣费状态不明的图片按它最多可能花的钻石计入）。
- 只用免费额度（`/budget off` 或 `--max-spend 0`）要服务端确认支持「只用免费额度」才会发送；没确认之前一条也不发，并提示怎样继续。只用免费额度、或在预算下，按免费发出的回复（或图片）被扣了钻石会立即暂停；不设预算时只计入累计花费。
- 生图（`/image`）：要花钻石的图片和回复一样，不设上限时直接发起（会先显示一次价格），设了上限时要在剩余额度内，只用免费额度时不发起。显示免费的图片在设了本机上限时，它的原价也要在 `--max-spend` 还能花的范围内（免费次数只是快照）。图片在送达时扣费，按任务自己的扣费状态计入（不看同期余额变化）。设了上限时，图片的任务结束、扣费结算之前不会发出新的消息或生图（已送达但扣费还没到账的，从送达起最多再等 180 秒）；不设上限时，结果未知、进度读不到或扣费还没到账的图片不会挡住新的消息，这些消息各自核对花费，图片的花费还没结算时每条最多按报价计入；正在生成的图片仍然一次一张。图片一律按任务计入，从不按余额；扣费状态一直不明的图片按它最多可能花的钻石计入，这会算进预算和 `--max-spend`。图片结算之前，它最多可能花的钻石从本机上限里预留（这台电脑上登记的每个 bot 的图片都算，这次没运行的也算）；剩下的额度都被预留时，提示等图片完成后再发，不用重启。

## 隐私与内容

- 只转发服务端审核过的段落（`paragraphs`）；生成过程中的原始文本和思考内容从不发到聊天平台。
- 只转发本 relay 自己发起的回复：你在 App 或网页上和同一角色聊天，不会出现在聊天平台里。
- 对话会经过聊天平台（Telegram、QQ、微信）的服务器，由它按自己的隐私政策处理；在 Yomi 里删除会话不会删掉聊天平台里的消息。
- **现在**：relay 在会话开始和之后每 3 小时显示一条 AI 提示（含「陪伴类聊天机器人可能不适合部分未成年人」）。服务端注入合规提示后，改为只转发服务端的提示。
- 本机只保存 relay 需要的最少信息（`~/.config/yomi-cli/relay/*.json`，0600，每个 bot 一份）：你在这个平台上的用户 ID（Telegram 还有名字）、当前角色、预算、聊天消息与 Yomi 消息 ID 的对应（用于举报，最多 500 条）、发过介绍的主人（用户 ID 的哈希，不存原值，和当时的角色，最多 20 个），以及通道自己需要的少量状态（例如还没送达的提醒）。凭证不在这些文件里，只在系统钥匙串（或 `--allow-file-store` 时单独的 0600 文件）里。`yomi relay --forget --bot <名字>` 删除一个 bot 的凭证和这些信息；`yomi relay --channel <通道> --forget` 删除这个通道唯一的 bot（以及这个通道的后台服务），有多个时会被拒绝；`yomi relay --forget --all` 删除全部 bot、后台服务和花费记录。
- 本机的 bot 登记在 `~/.config/yomi-cli/relay/bots-<哈希>.json`（0600，每个 Yomi 账号和环境一份）：每个 bot 的名字、通道、平台上的 bot ID、当前角色，以及它的凭证、状态文件和锁文件的名字；不含凭证，主人只存用户 ID 的哈希。升级后第一次运行 `yomi relay` 时，已经设置好的 bot 会自动登记，主人、预算、待核对的花费和收消息的进度都保留，不会重发介绍。`yomi relay --list`（可以加 `--channel`）列出这些 bot 和各自的状态，不做任何改动。钥匙串里的凭证如果被换成了另一个 bot 的（例如旧版本的 `--set-token`），relay 不会把它当成登记的 bot 启动：用 `yomi relay --bot <名字> --set-token`（QQ `--set-app`，微信 `--login`）重新设置它自己的凭证，或者用 `--forget --bot <名字>` 删掉它。
- **添加和重新设置 bot**：`--set-token`（QQ `--set-app`，微信 `--login`）加上 `--character <ID>` 会添加一个新的 bot，固定和这个角色聊天（名字默认取 Telegram 用户名、`qq-<AppID 后 4 位>` 或 `wechat-<序号>`，也可以用 `--bot <新名字>` 指定）；加上 `--bot <已有的名字>` 只重新设置这个 bot 的凭证，而且必须是同一个 bot（同一个 Telegram bot、同一个 AppID；微信是同一个 ClawBot，或这个 bot 换人扫码）。两个都不加时：这个通道还没有 bot 就添加一个（之后再绑定角色），正好有一个就重新设置它，有多个时会要求用 `--bot` 指定。同一个 bot、同一个角色都不能登记两次；新 bot 的凭证在钥匙串里用自己的名字保存，保存失败时什么都不会留下。
- **一个进程运行多个 bot**：不带 `--channel` 运行 `yomi relay`，会在一个进程里运行这台电脑上登记的所有 bot（`--channel <通道>` 只运行这个通道的，`--bot a,b` 只运行这几个；`--bot` 后面没有名字会被拒绝）。每一次 `yomi relay` 都这样运行，只运行一个通道或一个 bot 时也一样，所以这条说的共用花费记录，和「钱」里关于图片和差额的规则，对它们同样适用。它们共用一次 Yomi 登录、一条长连接和一份花费记录 `~/.config/yomi-cli/relay/ledger-<哈希>.json`（第一次运行时由各 bot 的记录合并而来）：`--max-spend` 是这个进程里所有 bot 共用的上限，`/budget` 仍然归各个 bot 的主人。不设上限时 bot 之间互不等待：另一个 bot 正在按余额核对花费时，这条消息按服务端报的扣费计入，没有报就按报价估计（日志里会注明）；设了上限时，按余额核对的发送轮流进行。一个 bot 出问题（被别的程序占用、凭证失效、反复意外停止）只停它自己，其他 bot 继续运行；意外停止的会稍后自动重新启动。运行中各 bot 的状态写在 `relay/hub-<哈希>.status.json`，`--list` 会显示。

## 一直运行（后台服务）

先在终端里完成配对（微信：先登录），再：

```sh
yomi relay --channel telegram --install-service                    # macOS: launchd LaunchAgent；Linux: systemd --user；不设上限
yomi relay --channel telegram --max-spend 200 --install-service    # 或者：本机累计最多花 200 钻石
yomi relay --channel telegram --service-status
yomi relay --channel telegram --uninstall-service
```

- 安装时会说明这个服务的花费上限（没有、0 或多少）：后台服务没有人看着，装之前想清楚。
- `--install-service` 带的 `--character` 只给还没有角色的 bot 绑定角色（服务启动时绑定；这个角色已经绑在别的 bot 上时，安装会被拒绝）。已经绑定角色的 bot 不会写进服务的命令行：角色不同时安装时会提示，要换角色用 `yomi relay --bot <名字> --character <ID>`。
- 旧版本装的服务在命令行里写着 `--max-spend 0`（当时不加这个参数就是 0），所以它们仍然只用免费额度，聊天里会提示。要按 Yomi 的正常规则扣费，用不带 `--max-spend` 的命令重新 `--install-service`（会先停掉并替换旧的服务）。

- 每个通道有自己的服务：Telegram 是 `io.yomichat.yomi-cli.relay.<环境>`（Linux `yomi-relay-<环境>.service`，和以前一样），QQ 是 `….relay.qq-<环境>`（`yomi-relay-qq-<环境>.service`），微信是 `….relay.wechat-<环境>`（`yomi-relay-wechat-<环境>.service`）。
- 服务里没有任何凭证：启动时从钥匙串读。macOS 的登录钥匙串在你登录后才可用，所以服务只在你登录期间工作；Linux 需要桌面会话里的 Secret Service（无人值守时 `loginctl enable-linger` 并解锁 keyring，或明确使用 `--allow-file-store`）。
- 日志在 `~/.config/yomi-cli/logs/`，只记录状态（连接、转发了一条、花费），不记录消息内容和凭证。
- 遇到「另一个程序在用这个 bot 收消息」「凭证失效」「电脑上登录的账号变了」这类重启也解决不了的情况，relay 会说明原因并正常退出，服务不会反复重启。
- 同一个 bot 同时只能运行一个 relay（本机锁文件；Telegram 还有它自己的 409）。

## 断线与恢复

- Yomi 长连接无限次重连，电脑休眠唤醒后立即重连；每次连上先读 `poll_message` 补齐离线期间的推送，回复超时（默认 120 秒）后按消息 ID 读历史。
- Yomi 登录失效时 relay 暂停，并在聊天里提醒你；在电脑上 `yomi login` 之后自动恢复。
- relay 和 `yomi create` 等命令同时刷新会话时会排队，不会互相把对方登出。

## Telegram

`--telegram` 和 `--channel telegram` 完全相同，下面用短的写法。

### 准备

1. `yomi login`。
2. 在 Telegram 里找 @BotFather，`/newbot` 建一个**专用**的 bot（不要用已经接了别的服务的 bot：relay 发现 webhook 会拒绝启动）。
3. 保存 token：

   ```sh
   yomi relay --telegram --set-token          # 粘贴 token，不显示
   # 或者（脚本里）：
   some-secret-manager read telegram-bot | yomi relay --telegram --set-token --token-stdin
   ```

### 运行与配对

```sh
yomi relay --telegram --character 7300000000000009001
```

第一次运行时终端会显示配对码，在 Telegram 里给你的 bot 发 `/start 配对码`（或 `/pair 配对码`），或打开终端里给出的 `t.me/...?start=...` 链接。配对成功后，bot 接着发 AI 提示、角色的封面图、简介和开场白（或最近一条回复，见[运行与配对](#运行与配对)）。配对之后，这个 bot 只处理你本人（同一个 Telegram 账号、私聊）的消息；有人把 bot 拉进群，它会自动退出。要换人或重新配对：`yomi relay --telegram --pair`。

### Telegram 的不同之处

- 回复以 Telegram 的「思考中」草稿流式出现，可以点「停止」；`--no-drafts` 改为编辑消息。
- 确认用按钮；回复（引用）某条消息再发 `/report` 或 `/image`，就针对那一条。
- 本机保存你的 Telegram 用户 ID 和名字（Bot Developer Terms §4.2 允许的最少信息）。
- token 可能泄露时，在 @BotFather 里用 `/revoke` 让它失效，再 `yomi relay --telegram --set-token` 换新的；有多个 Telegram bot 时用 `yomi relay --bot <名字> --set-token`。
