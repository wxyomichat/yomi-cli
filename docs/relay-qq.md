# yomi relay --channel qq

**仅限个人使用**：relay 只转发你本人和你自己的 QQ 机器人之间的私聊（单聊）消息。不要把这个机器人给别人用，也不要拉进群：群消息一律忽略。

通用的运行方式、聊天里的命令、钱、隐私和后台服务见 [docs/relay.md](relay.md)。本文只写 QQ 自己的部分。

## 0. 最快：yomi relay --setup

```sh
yomi relay --setup
```

在终端里一步步带你做完下面第 1–3 节的事，大约 10 分钟：选角色 → 在 q.qq.com 创建机器人 → 用手机 QQ 扫码取得 AppID 和 AppSecret，或者手动输入（AppSecret 不显示；向 QQ 核对后才往下走）→ 检查私聊权限并保存 → 选之后怎样运行（在这个终端里、装成后台服务，或者只配对）→ 加机器人为 QQ 好友 → 连接并配对。需要在 QQ 那边操作的步骤，按 `o` 会在浏览器里打开 QQ 的官方页面。

- 只在终端里用：脚本和管道里用第 2 节的 `--set-app --token-stdin`，再在终端里 `yomi relay --bot <名字> --pair`。
- 随时可以按 Ctrl+C 或 `q` 退出。「检查私聊权限并保存」那一步之后，bot 就留在这台电脑上（没登录 Yomi 时，最前面多一步「登录 Yomi」，后面的步骤号都加 1）；再运行 `yomi relay --setup` 会从上次停下的地方接着做（也可以用 `--bot <名字>` 直接选）。已经设置完的 bot，`--setup` 会带你重新设置它的 AppSecret。
- 可以先填好的：`--character <ID>`、`--bot <名字>`、`--max-spend <数量>`（花费上限，用于之后在终端里运行或装成后台服务；已经装了后台服务时，必须和服务的上限一致），以及 `--allow-file-store`、`--confirm-prod`。
- AppID、角色链接和花费上限只显示其中的数字；粘贴到别处的 AppSecret 不会显示，也不会保存。
- 配对在同一个进程里完成：引导会说出 QQ 那边的结果，例如你还不是机器人的好友（40054004）时，机器人回复不了你。
- 暂时只支持 QQ。Telegram 用 `--set-token`，微信用 `--login`。

### 扫码取得 AppID 和 AppSecret

添加新的 bot 时，第 3 步默认在终端里画一个二维码。用手机 QQ 扫码，按手机上的提示选择刚创建的机器人并确认，yomi 就拿到它的 AppID 和 AppSecret，不用复制粘贴，AppSecret 也不会显示出来。拿到的 AppID 和 AppSecret 和手动输入的一样，先向 QQ 核对，再往下走。

- 扫码页会把接入方显示为「第三方机器人」：那就是这里的 yomi。腾讯的扫码页对接入方默认都这样显示，要显示别的名字得和腾讯另外商量。
- 二维码来自腾讯的扫码 SDK [`@tencent-connect/qqbot-connector`](https://www.npmjs.com/package/@tencent-connect/qqbot-connector)（固定用 1.2.0，它依赖的 `qrcode-terminal` 也固定为 0.12.0；npm 上的许可证字段是 `UNLICENSED`，闭源，发布的代码经过压缩混淆）。它是 yomi 唯一不开源的依赖，所以 yomi 只在一个单独的子进程里运行它，把它和 yomi 的设置、登录信息以及终端隔开：
  - 子进程只拿到 `PATH`、`LANG`、`LC_*` 和 `TZ` 这几个环境变量：yomi 不把 Yomi 的设置（`YOMI_*`）、`HOME` 和登录信息交给它，子进程里也不加载 yomi 自己的代码；
  - 它的标准输入、输出和错误输出都不接终端，yomi 只从进程间通道接收它交回的二维码链接和扫码得到的 AppID、AppSecret；
  - yomi 检查它交回的每一条内容：二维码链接只能是 `https://q.qq.com/` 开头的地址（不能带 `\` 或 `@`），AppID 只能是数字，AppSecret 的长度和字符要像 QQ 给的那样；不对就结束它，改为手动输入。二维码由 yomi 自己画，扫码结束后从终端里擦掉；
  - 扫码成功、失败、超时、按 `m` 或 `q`、按 Ctrl+C，以及 yomi 退出时，这个子进程都会被结束。
- 这只是不把东西交给它，不是沙箱：子进程仍以你的系统用户身份运行，你自己能读的文件和钥匙串条目，它也读得到（包括 yomi 保存登录信息和 AppSecret 的地方）。不想运行它的话，不用 `--setup`，改用第 2 节的 `--set-app` 手动保存 AppID 和 AppSecret：`--set-app` 从不启动扫码组件。
- 手动输入一直可用：扫码时按 `m` 改为手动输入；扫码失败、5 分钟内没有扫完，或者扫码组件加载不了时，引导会说明原因，自动改为手动输入（在哪里复制，见第 1 节第 2 条）。重新设置已有 bot 的 AppSecret 时只用手动输入。`--set-app` 不扫码。
- 扫码要连腾讯的 q.qq.com；连不上（网络、代理）时同样改为手动输入。

## 1. 在 QQ 开放平台创建自己的机器人

1. 用你自己的 QQ 登录 [QQ 开放平台](https://q.qq.com/#/apps)，在「机器人」页点「去创建或管理我的 QQ 机器人」，再点「+ 创建机器人」，填头像、昵称和简介（以后都能改）。按 QQ 的说明，创建会立刻成功，机器人随后会给创建者发一条 QQ 消息。认证过的个人最多可以建 5 个机器人。平台要求完善主体认证时，按控制台的提示做。不要冒用别人的名字或头像（[运营规范](https://bot.q.qq.com/wiki/business/)）。
2. 创建后会进入「设置 AI 服务」页。在「手动绑定参数」里复制 **AppID** 和 **AppSecret**，然后点「稍后连接」。**不要在这页连接别的 AI 服务**：同一个机器人接到两处，消息会被那边收走。用已有的机器人时，在它的「开发设置 → APPID 接入凭证」里找 AppID 和 AppSecret，并确认它没有接着别的 AI 服务或程序。AppSecret 相当于密码，只在自己的电脑上输入。QQ 旧版的页面写明，再次查看 AppSecret 会强制重置它，新控制台可能也是这样：如果你又看了一次，就用新的那个。
3. 在这个机器人的「开发设置」里确认两件事：
   - 「事件订阅与回调地址」用的是 WebSocket 方式（控制台写「当前以 WebSocket 方式接收事件推送」）。
   - 「服务器 IP 白名单」是空的（空表示不限制来源 IP，这是默认的），或者里面有这台电脑现在的公网 IPv4（家里的公网 IP 会变）。
4. 确认这个机器人能接收单聊消息：relay 订阅的是 QQ 的「群和单聊事件」（`GROUP_AND_C2C_EVENT`）。QQ 说它没有这个权限时（4014），`--set-app` 会提示，relay 启动后会停止，不会反复重试。QQ 的文档没有写这个权限在哪里开启：先确认上一条的 WebSocket 方式，还不行的话，看 QQ 的[常见问题](https://bot.q.qq.com/wiki/bot_FAQ/)或联系 QQ。QQ 说 intent 无效时（4013），是这个版本的 yomi 和 QQ 网关的协议对不上，请升级 yomi。
5. **加机器人为 QQ 好友**。QQ 只允许机器人给好友发单聊消息，不是好友时 QQ 返回 40054004，relay 的回复发不出去（日志会提示，消息会排队）。在 q.qq.com 打开这个机器人，点顶部名字旁边的二维码（刚创建时，也可以用「设置 AI 服务」页上的「扫码对话」），用手机 QQ 扫码，按 QQ 的提示加好友。
   - 要用另一个 QQ 号聊天（不是登录 q.qq.com 的那个号）：先在「开发设置 → 开发体验号码设置」里把那个号加进去（最多 20 个），否则它加不了机器人。
   - 「服务范围 → 好友（私聊） → 允许被其他 QQ 用户添加使用」保持关闭（默认就是关闭的），这样只有你和体验号码能加它为好友。

relay 不用 webhook，也不需要公网地址：它从你的电脑主动连 QQ 的官方 WebSocket 网关收消息，用 QQ 的接口回复。

## 2. 保存 AppID 和 AppSecret

```sh
yomi relay --channel qq --set-app
```

先输入 AppID（会显示），再输入 AppSecret（不显示）。也可以从标准输入传入，第一行 AppID、第二行 AppSecret：

```sh
printf '%s\n%s\n' "$APPID" "$APPSECRET" | yomi relay --channel qq --set-app --token-stdin
```

- relay 先用它们向 QQ 换一个访问令牌（access token），QQ 不接受时不会保存。
- 然后连一次 QQ 网关，确认这个机器人有单聊事件的权限；这会用掉 QQ 每天给这个机器人的连接次数中的一次。没有权限时只提示，照常保存。
- AppID 和 AppSecret 存在系统钥匙串里（没有钥匙串时，要加 `--allow-file-store` 才会存进 0600 权限的本地文件）；访问令牌只在内存里，快过期时自动换新。它们都不接受命令行参数和环境变量，也不会出现在日志里。
- 终端里有 relay 在运行时 `--set-app` 会被拒绝：先停止 relay；后台服务在运行时，命令会先停止它，保存完再重新启动。
- 已经有 QQ bot 时，`--set-app` 只重新设置它自己的 AppSecret（AppID 必须相同，否则在连接 QQ 之前就会被拒绝）；要再添加一个 QQ bot，加 `--character <ID>` 或 `--bot <新名字>`，再用 `yomi relay --bot <名字> --pair` 配对（多个 bot 的命令见 [docs/relay.md](relay.md#多个-bot)）。

## 3. 配对

```sh
yomi relay --channel qq --character 7300000000000009001
```

第一次运行时终端会显示一个配对码，在和机器人的私聊里发送：

```
/pair ABCD-EFGH
```

配对码 15 分钟内有效、只能用一次，只显示在这个终端里，不要发给别人。配对成功后，机器人在同一条消息下接着发介绍：「已配对」、当前角色和 AI 提示合成一条，然后是角色的封面图，再是简介和开场白（或最近一条回复，见 [docs/relay.md](relay.md#运行与配对)）。服务端还没确认 QQ 通道时，介绍等确认后你的下一条消息时再发。配对之后只有你的消息会转给 Yomi；别人的消息不会转发，也不会扣费。要换人，用 `--pair` 重新生成配对码。QQ 不提供对方的昵称，所以日志里的主人只记 QQ 给的 openid。

可选：在 q.qq.com 控制台里给机器人配置指令菜单（`/help`、`/price`、`/budget`、`/image`、`/report`、`/stop`），方便在手机上点选；不配置也可以直接打字。

后台服务：`yomi relay --install-service` 装一个服务，在一个进程里运行这台电脑上的全部 bot（QQ 的和其他通道的），名字和细节见 [docs/relay.md](relay.md#一直运行后台服务)。旧版本装的 QQ 服务（macOS 是 `io.yomichat.yomi-cli.relay.qq-<环境>`，Linux 是 `yomi-relay-qq-<环境>.service`）会在 `--install-service` 时停止并删除。服务运行时配对一个 QQ bot（`yomi relay --bot <名字> --pair`），命令会先停止服务，在终端里显示配对码，配对完成后再重新启动服务，这期间所有 bot 都离线。同一个 Yomi 账号和环境，本机同时只能运行一个 relay 进程。

## 4. 能力与限制

| 项目             | QQ 上的情况                                                                                                                                                                                                                                                              |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 回复怎样出现     | 用 QQ 的流式消息：写完的段落先出现，正在写的最后一段在回复结束时一起出现。审核改动了已经显示的段落时，relay 会撤回这条流式消息（QQ 只允许 2 分钟内撤回），再把最终回复作为新消息发出                                                                                     |
| 格式             | 纯文本：旁白放在（）里，群聊角色写「名字：台词」。QQ 的 markdown 已实现但暂不启用，要先在真机上确认显示效果                                                                                                                                                              |
| 单条长度         | 按 2000 字处理，更长的回复拆成几条（QQ 的实际上限待核实）                                                                                                                                                                                                                |
| 回复次数和时限   | QQ 允许机器人回复你的每条消息若干次。QQ 的文档有的写 5 分钟、有的写 60 分钟，relay 按保守的「4 分 30 秒内、最多 4 次」处理。同一段时间里的提示（AI 提示、价格、离线消息、回复后的提示）会合并成一条，尽量少占次数。配对消息的介绍占其中 3 次（文字、封面、简介和开场白） |
| 时限外的消息     | 主动消息（QQ 限制每人每分钟 20 条、每天 1000 条）。你在 QQ 里关闭「允许主动消息」，或 QQ 限频时，消息会排队，等你下次发消息时放在回复的开头一起发出                                                                                                                      |
| 排队             | 最多 20 条，超过 24 小时的不再发。排队的图片每条消息只带一张，其余的提示你到 Yomi App 查看。relay 退出时还没发出的提示也会排队                                                                                                                                           |
| 需要你确认的操作 | 没有按钮：`/budget`、`/report` 的选项带编号和一次性代码，回复「代码 序号」（例如 `K7Q2 1`），10 分钟内有效                                                                                                                                                               |
| 引用某条回复     | 暂不支持：`/report` 和 `/image` 针对最近一条回复                                                                                                                                                                                                                         |
| 「正在输入」提示 | 不发送（它可能占用一次回复，待核实）                                                                                                                                                                                                                                     |
| 停止生成         | 发 `/stop`（QQ 没有停止按钮）                                                                                                                                                                                                                                            |
| 图片             | `/image` 的结果直接上传给 QQ，单张 5 MB 以内（超过时发缩略图）；介绍里的角色封面同样上传，超过 5 MB 时不发封面                                                                                                                                                           |
| 群聊、频道       | 不支持，消息一律忽略                                                                                                                                                                                                                                                     |

## 5. relay 离线时发的消息

和 Telegram 不同，**QQ 不会把 relay 离线时发给机器人的消息补发过来**：

- 短暂断线（网络波动、电脑睡眠后醒来）时，relay 会恢复原来的连接，按 QQ 的文档，QQ 会补发这段时间的消息。relay 5 分钟内重启时也会先尝试恢复原来的连接；QQ 是否允许新进程恢复还要在真实账号上确认，不允许时按下一条处理。relay 记得已经处理过哪些消息，所以补发时同一条消息不会转发两次、也不会扣两次费。
- relay 停得更久时，这期间发的消息机器人收不到。重新连上后，你发的第一条消息会附带一句提示：「relay 离线期间发给这个 QQ bot 的消息没有收到，需要的话请重新发送」。
- 和其他通道一样，超过 10 分钟的旧消息不会补转，以免意外扣费。

## 6. 内容规则

QQ 机器人要遵守 QQ 的运营规范：要有内容过滤和未成年人提醒，不能冒用他人名义。QQ 按内容规则拒绝某条回复时（40034006）：

- relay 不会重发这段文字，已经显示的部分保留；
- 每次运行只提醒你一次；
- 一次运行里被拒 3 次后，relay 暂停转发（命令照常可用），在电脑上重新启动 relay 才恢复。

QQ 的常见问题里写着，机器人输出违规可能被封禁且「暂不支持解封」。QQ 下架（4914）或封禁（4915）机器人时，relay 会说明原因并停止，不会反复连接。

## 7. 只在一台电脑上运行

本机的锁只能防止同一台电脑上运行两个 relay。如果两台电脑用同一个 AppID 同时运行，两边都可能回复、都可能扣费：同一个机器人只在一台电脑上运行 relay。

## 8. AppSecret 泄露时

只有一个 QQ bot 时：

1. 停止 relay，删除本机保存的凭证和配对：`yomi relay --channel qq --forget`（QQ 旧版的后台服务也会一起删除；其他通道的 bot 和凭证不受影响，所有 bot 共用的后台服务在运行时会先停止，删除后再重新启动，删掉的是最后一个 bot 时不再启动）。
2. 在 q.qq.com 这个机器人的「开发设置 → APPID 接入凭证」里重置 AppSecret（QQ 建议定期重置，怀疑泄露时立即重置；按钮的名字以控制台为准）。
3. 用新的 AppSecret 重新 `yomi relay --channel qq --set-app`。

有多个 QQ bot 时，不用先删除：在 q.qq.com 重置这个机器人的 AppSecret，再用新的 AppSecret 运行 `yomi relay --bot <名字> --set-app`（名字见 `yomi relay --list`）。AppID 不变，主人和记录都保留；后台服务在运行时会先停止它，保存完再重新启动。

还在运行的 relay 在 AppSecret 被重置后会提示「QQ 不认这个 AppID/AppSecret」并停止。

## 9. 隐私

对话会经过腾讯的服务器，由 QQ 按自己的隐私政策处理；在 Yomi 里删除会话不会删掉 QQ 里的消息。relay 的状态文件里保存主人的 openid、已处理消息的 id、网关的连接位置（用于恢复连接），以及排队等你下次发消息时再发的内容（`--forget` 会一起删除）。

## 10. 还要在真实账号上确认的地方

以下按保守的方式实现，在真实的 QQ 机器人上验证后可能调整：被动回复的时限（5 分钟还是 60 分钟）、流式消息算不算一次回复、单条消息的长度上限、markdown 的转义和换行、「正在输入」是否占用回复次数、引用回复的字段、新建的个人机器人是否默认有单聊事件权限、新建的机器人是否默认用 WebSocket 方式接收事件、重启后的 relay 能否恢复原来的连接、两台电脑同时连接时 QQ 怎样处理。

控制台的 IP 白名单：按 QQ 的文档，白名单是空的（默认）时不限制来源 IP，所以家用网络不受影响；加了 IP 以后才会限制。白名单管不管换取令牌和网关连接、拦下时 QQ 返回什么错误码，还要在真实账号上确认。
