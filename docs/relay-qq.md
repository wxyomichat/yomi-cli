# yomi relay --channel qq

**仅限个人使用**：relay 只转发你本人和你自己的 QQ 机器人之间的私聊（单聊）消息。不要把这个机器人给别人用，也不要拉进群：群消息一律忽略。

通用的运行方式、聊天里的命令、钱、隐私和后台服务见 [docs/relay.md](relay.md)。本文只写 QQ 自己的部分。

## 1. 在 QQ 开放平台创建自己的机器人

1. 用你自己的 QQ 登录 [QQ 开放平台](https://q.qq.com)，在机器人列表里点「创建机器人」。按 QQ 的说明，创建会立刻成功，机器人随后会给创建者发一条 QQ 消息；头像和昵称可以改。个人主体最多可以建 5 个机器人。平台要求完善主体认证时，按控制台的提示做。
2. 在这个机器人的管理页里找到「开发管理」（旧版控制台叫「开发设置」，以控制台为准），记下 **AppID** 和 **AppSecret**。AppSecret 可能要先点「生成」并按提示确认，之后控制台未必再显示原值，所以生成后直接输入给 relay。AppSecret 相当于密码，只在自己的电脑上输入。
3. 确认这个机器人能接收单聊消息：relay 订阅的是 QQ 的「群和单聊事件」（`GROUP_AND_C2C_EVENT`）。没有这个权限时，`--set-app` 会提示，relay 启动后会以「没有私聊（单聊）消息事件的权限（4014）」停止，不会反复重试。
4. **加机器人为 QQ 好友**。QQ 只允许机器人给好友发单聊消息，不是好友时 QQ 返回 40054004，relay 的回复发不出去（日志会提示，消息会排队）。

relay 不用 webhook，也不需要公网地址：它从你的电脑主动连 QQ 的官方 WebSocket 网关收消息，用 QQ 的接口回复。

## 2. 保存 AppID 和 AppSecret

```sh
yomi relay --channel qq --set-app
```

先输入 AppID（会显示），再输入 AppSecret（不显示）。也可以从标准输入传入，第一行 AppID、第二行 AppSecret：

```sh
printf '%s\n%s\n' "$APPID" "$APPSECRET" | yomi relay --channel qq --set-app --token-stdin
```

- relay 先用它们向 QQ 换一个访问令牌（access token），QQ 不接受时不会保存。
- 然后连一次 QQ 网关，确认这个机器人有单聊事件的权限；这会用掉 QQ 每天给机器人的一次连接次数。没有权限时只提示，照常保存。
- AppID 和 AppSecret 存在系统钥匙串里（没有钥匙串时，要加 `--allow-file-store` 才会存进 0600 权限的本地文件）；访问令牌只在内存里，快过期时自动换新。它们都不接受命令行参数和环境变量，也不会出现在日志里。
- 终端里有 relay 在运行时 `--set-app` 会被拒绝：先停止 relay；后台服务在运行时，命令会先停止它，保存完再重新启动。
- 已经有 QQ bot 时，`--set-app` 只重新设置它自己的 AppSecret（AppID 必须相同，否则在连接 QQ 之前就会被拒绝）；要再添加一个 QQ bot，加 `--character <ID>` 或 `--bot <新名字>`。

## 3. 配对

```sh
yomi relay --channel qq --character 7300000000000009001
```

第一次运行时终端会显示一个配对码，在和机器人的私聊里发送：

```
/pair ABCD-EFGH
```

配对码 15 分钟内有效、只能用一次，只显示在这个终端里，不要发给别人。配对成功后，机器人在同一条消息下接着发介绍：「已配对」、当前角色和 AI 提示合成一条，然后是角色的封面图，再是简介和开场白（或最近一条回复，见 [docs/relay.md](relay.md#运行与配对)）。服务端还没确认 QQ 通道时，介绍等确认后你的下一条消息时再发。配对之后只有你的消息会转给 Yomi；别人的消息不会转发，也不会扣费。要换人，用 `--pair` 重新生成配对码。QQ 不提供对方的昵称，所以日志里的主人只记 QQ 给的 openid。

可选：在 q.qq.com 控制台里给机器人配置指令菜单（`/help`、`/price`、`/budget`、`/image`、`/report`、`/stop`），方便在手机上点选；不配置也可以直接打字。

后台服务：`yomi relay --channel qq --install-service`（macOS 是 `io.yomichat.yomi-cli.relay.qq-<环境>`，Linux 是 `yomi-relay-qq-<环境>.service`）。同一个 Yomi 账号和环境，本机同时只能运行一个 relay。

## 4. 能力与限制

| 项目             | QQ 上的情况                                                                                                                                                                                                                                                              |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 回复怎样出现     | 用 QQ 的流式消息：写完的段落先出现，正在写的最后一段在回复结束时一起出现。审核改动了已经显示的段落时，relay 会撤回这条流式消息（QQ 只允许 2 分钟内撤回），再把最终回复作为新消息发出                                                                                     |
| 格式             | 纯文本：旁白放在（）里，群聊角色写「名字：台词」。QQ 的 markdown 已实现但暂不启用，要先在真机上确认显示效果                                                                                                                                                              |
| 单条长度         | 按 2000 字处理，更长的回复拆成几条（QQ 的实际上限待核实）                                                                                                                                                                                                                |
| 回复次数和时限   | QQ 允许机器人回复你的每条消息若干次。QQ 的文档有的写 5 分钟、有的写 60 分钟，relay 按保守的「4 分 30 秒内、最多 4 次」处理。同一段时间里的提示（AI 提示、价格、离线消息、回复后的提示）会合并成一条，尽量少占次数。配对消息的介绍占其中 3 次（文字、封面、简介和开场白） |
| 时限外的消息     | 主动消息（QQ 限制每人每分钟 20 条、每天 1000 条）。你在 QQ 里关闭「允许主动消息」，或 QQ 限频时，消息会排队，等你下次发消息时放在回复的开头一起发出                                                                                                                      |
| 排队             | 最多 20 条，超过 24 小时的不再发。排队的图片每条消息只带一张，其余的提示你到 Yomi App 查看。relay 退出时还没发出的提示也会排队                                                                                                                                           |
| 需要你确认的操作 | 没有按钮：`/budget`、`/report` 的选项带编号和一次性代码，回复「代码 序号」（例如 `K7Q2 1`），10 分钟内有效                                                                                                                                                               |
| 引用某条回复     | 暂不支持：`/report` 和 `/image` 针对最近一条回复                                                                                                                                                                                                                         |
| 「正在输入」提示 | 不发送（它可能占用一次回复，待核实）                                                                                                                                                                                                                                     |
| 停止生成         | 发 `/stop`（QQ 没有停止按钮）                                                                                                                                                                                                                                            |
| 图片             | `/image` 的结果直接上传给 QQ，单张 5 MB 以内（超过时发缩略图）；介绍里的角色封面同样上传，超过 5 MB 时不发封面                                                                                                                                                           |
| 群聊、频道       | 不支持，消息一律忽略                                                                                                                                                                                                                                                     |

## 5. relay 离线时发的消息

和 Telegram 不同，**QQ 不会把 relay 离线时发给机器人的消息补发过来**：

- 短暂断线（网络波动、电脑睡眠后醒来）时，relay 会恢复原来的连接，按 QQ 的文档，QQ 会补发这段时间的消息。relay 5 分钟内重启时也会先尝试恢复原来的连接；QQ 是否允许新进程恢复还要在真实账号上确认，不允许时按下一条处理。relay 记得已经处理过哪些消息，所以补发时同一条消息不会转发两次、也不会扣两次费。
- relay 停得更久时，这期间发的消息机器人收不到。重新连上后，你发的第一条消息会附带一句提示：「relay 离线期间发给这个 QQ bot 的消息没有收到，需要的话请重新发送」。
- 和其他通道一样，超过 10 分钟的旧消息不会补转，以免意外扣费。

## 6. 内容规则

QQ 机器人要遵守 QQ 的运营规范：要有内容过滤和未成年人提醒，不能冒用他人名义。QQ 按内容规则拒绝某条回复时（40034006）：

- relay 不会重发这段文字，已经显示的部分保留；
- 每次运行只提醒你一次；
- 一次运行里被拒 3 次后，relay 暂停转发（命令照常可用），在电脑上重新启动 relay 才恢复。

QQ 的常见问题里写着，机器人输出违规可能被封禁且「暂不支持解封」。QQ 下架（4914）或封禁（4915）机器人时，relay 会说明原因并停止，不会反复连接。

## 7. 只在一台电脑上运行

本机的锁只能防止同一台电脑上运行两个 relay。如果两台电脑用同一个 AppID 同时运行，两边都可能回复、都可能扣费：同一个机器人只在一台电脑上运行 relay。

## 8. AppSecret 泄露时

只有一个 QQ bot 时：

1. 停止 relay，删除本机保存的凭证和配对：`yomi relay --channel qq --forget`（后台服务也会一起删除；其他通道的凭证不受影响）。
2. 在 q.qq.com 的机器人管理端重置 AppSecret（QQ 建议定期重置，怀疑泄露时立即重置）。
3. 用新的 AppSecret 重新 `yomi relay --channel qq --set-app`。

有多个 QQ bot 时，不用先删除：在 q.qq.com 重置这个机器人的 AppSecret，再用新的 AppSecret 运行 `yomi relay --bot <名字> --set-app`（名字见 `yomi relay --list`）。AppID 不变，主人和记录都保留；后台服务在运行时会先停止它，保存完再重新启动。

还在运行的 relay 在 AppSecret 被重置后会提示「QQ 不认这个 AppID/AppSecret」并停止。

## 9. 隐私

对话会经过腾讯的服务器，由 QQ 按自己的隐私政策处理；在 Yomi 里删除会话不会删掉 QQ 里的消息。relay 的状态文件里保存主人的 openid、已处理消息的 id、网关的连接位置（用于恢复连接），以及排队等你下次发消息时再发的内容（`--forget` 会一起删除）。

## 10. 还要在真实账号上确认的地方

以下按保守的方式实现，在真实的 QQ 机器人上验证后可能调整：被动回复的时限（5 分钟还是 60 分钟）、流式消息算不算一次回复、单条消息的长度上限、markdown 的转义和换行、「正在输入」是否占用回复次数、引用回复的字段、新建的个人机器人是否默认有单聊事件权限、重启后的 relay 能否恢复原来的连接、控制台的 IP 白名单是否限制从家用网络调用接口、两台电脑同时连接时 QQ 怎样处理。
