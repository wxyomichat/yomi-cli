# AI 生成：角色图片、视频、人设头像

yomi-cli 有四个地方用 AI 生成内容，都可能花钻石：

| 入口                  | 生成什么                                                 | 怎么计费                                                             |
| --------------------- | -------------------------------------------------------- | -------------------------------------------------------------------- |
| `yomi image`          | 角色图片，并裁好角色文件要用的封面（1:2）和头像（1:1）   | 按张：单价 × 张数。生成失败或没通过内容检查的那张单独退款            |
| `yomi video`          | 角色的动态封面或介绍视频，`yomi create` 时随角色一起提交 | 按报价：一条视频一个价格。生成失败或没通过内容检查时退款             |
| `yomi persona avatar` | 聊天人设（主控）的头像，选一张写进人设                   | 按成功的张数：生成失败或没通过内容检查的那张不计费                   |
| relay 的 `/image`     | 根据角色的一条回复生成一张图片，发到你的 Telegram        | 图片送达对话时扣费，走 relay 自己的预算（见[下文](#relay-的-image)） |

## 花钻石的规则

`image`、`video`、`persona avatar` 都按下面的规则来：

1. **先显示价格和余额。** 扣费之前，先显示这次要花多少（单价 × 数量，或视频的报价）和当前钻石余额。读不到余额就不继续；余额不够就不发新请求，并提示去 Yomi App 或网页充值（重发结果未知的请求时例外：已受理的不会再扣，没受理的会被服务端以余额不足拒绝）。价格为 0 时只说明免费，然后继续。
2. **明确同意价格。** 在终端里要输入 `yes`。非交互运行（脚本、CI）时要加 `--accept-price`，表示同意显示的价格；不加就不会发出付费请求。
3. **生产环境再确认一次。** 连生产环境时还要输入 `prod`（非交互时加 `--confirm-prod`）。测试环境和本地 mock 不问。
4. **只有一步扣费。** 每个命令里只有一个请求会扣费（下文各节标出）。这个请求发出之前，会连同它的请求 ID 先存到本机。配置、报价、上传、查询进度、下载结果都不扣费。
5. **按份退款。** 一次生成多张图时，每张单独计费、单独退款，一张失败不影响其它几张。
6. **「退款中」不等于「已退回」。** 只有服务端确认退款完成，CLI 才说「已退回」；还在处理时说「退款中」。失败后还没开始退款的，会说明退款还没有开始。可以稍后用 `--resume` 再看。
7. **明确拒绝不扣费。** 服务端明确拒绝（例如余额不足、参数不对）的那次请求没有扣费。第一次发送就被拒绝的，本机不再保留它，下次就是一个新请求。报错的回答里如果已经带着任务或批次，说明请求已被受理，不算拒绝。
8. **结果未知时不自动重发。** 网络断了、超时，或者服务端的回答不是 CLI 认识的明确拒绝时，CLI 无法确定这次有没有被受理、有没有扣费。这时它保留这次请求，并给出 `--resume <请求 ID>` 的命令。`--resume` 用**同一个请求 ID 和同一个请求体**重发；服务端按请求 ID 去重，已经受理的直接返回原来的结果，不会再扣费。
9. **不会自己重试付费请求。** 付费请求只在你同意之后发出；重发也只发本机保存的那一个，而且要你自己运行 `--resume`（`yomi image` 再运行完全相同的命令也会重发保存的那一个，见下文）。
10. **停止查看不会取消。** 生成在服务端进行。Ctrl+C 或者查询次数用完，只是停止查看，不会取消任务，也不会退款。之后可以用 `--resume` 继续查看，不会再扣费。

relay 的 `/image` 用的是 relay 的预算和本机花费上限，见 [relay 的 /image](#relay-的-image)。

## yomi image：角色图片

```bash
yomi image --options                                        # 模型、单价、风格、比例、张数上限（不扣费）
yomi image -p "雨夜书店里的店主，温柔的笑"                  # 默认第一个模型、不选风格、9:16、4 张
yomi image -p "…" --model <模型ID> --style <风格> --ratio 9:16 --count 2
yomi image -p "…" --reference ref.jpg                       # 带参考图
yomi image -p "…" --pick 2 --into lin-xia.yaml --as both    # 把第 2 张写进角色文件
yomi image --resume <批次ID或请求ID>                        # 继续查看、重新下载，或重发结果未知的请求
```

选项：

- `-p`：描述，必填，最多 1000 字（按 Unicode 码点计）。
- `--model`：默认第一个模型。`--style`：风格 ID 或名称，默认不选；每个模型可选的风格不同，见 `--options`。`--ratio`：默认 9:16，配置里没有 9:16 时用第一个比例。`--count`：1–4，默认 4，不超过服务端当前上限。配置里没有的值，在发出任何请求前就会报错。
- `--reference`：参考图，JPEG / PNG / WebP，不超过 20 MB，每边不超过 8192 px。同意价格之后先上传并审核（不扣费）；没通过审核就停下，不发生成请求。

流程：

1. 读生图配置（`npc/get_ugc_image_generation_config`）。功能没开放或者读不到这个模型的价格时，不继续。
2. 显示模型、风格、比例、张数，以及「单价 × 张数」的总价和余额。服务端给了更高的原价时，原价只作展示。输入 `yes`（或 `--accept-price`），生产环境再输入 `prod`。
3. 请求（请求 ID + 请求体）存到本机后，发送 `npc/create_ugc_image_generation_batch`。**这一步扣费。** 受理后显示批次 ID。
4. 每 2.5 秒查一次进度（`npc/batch_get_ugc_image_generation_tasks`），最多 120 次（约 5 分钟）。每张图都有了结果、并且没有「扣费确认中」或「退款中」的，才算结束。
5. 下载成功的图片（下载前重新读一次地址），逐张显示结果和扣费状态，最后汇总，例如「共扣 150 钻石，已退回 50 钻石」，或者还有「退款中」「扣费确认中」的金额。

服务端没有「我的生图批次」列表，批次 ID 只显示在终端上并记在本机。

### 写进角色文件：--pick / --into / --as

`--pick N --into 角色文件 --as cover|avatar|both` 把第 N 张裁好的封面和（或）头像写进 YAML 角色文件的 `cover` / `avatar`。这三个选项要一起用。

- 写入的是图片文件的路径，相对于角色文件所在目录。文件里的注释和字段顺序不变。只支持 YAML 角色文件，不支持 JSON。
- 角色文件在扣费前就会检查，读不了就不发请求。
- 之后 `yomi create` / `yomi preview` 会像对待其它本地图片一样上传并审核它们。
- 原图在本机裁不了（WebP 或解码失败）时，只保留原图，写入的是生成结果本身的引用 `{ asset_id: "…" }`，没有裁剪。如果创建时不被接受，请自己把原图裁好，再把路径写进角色文件。

### --resume

- 批次 ID，或已受理请求的请求 ID：只读取结果、重新下载，不会扣费。可以同时加 `--pick --into --as`。
- 结果未知的请求 ID：重新显示价格和余额，确认后用原来的请求 ID 和请求体重发。这时余额低于价格也可以重发：如果上次已经受理，就不会再扣；如果没有受理，服务端会因为余额不足拒绝。
- 重发被服务端拒绝（余额不足、配置版本变了、太频繁等）时，被拒的只是这次重发，没有扣费；但上次那次可能已经受理，所以请求和请求 ID 都保留，之后仍用同一个请求 ID 重发。确定不要了，用 `--resume <请求ID> --forget` 放弃，之后同样的命令会作为新请求重新扣费。
- `--resume <ID> --forget`：放弃本机对这个结果未知的请求、或还没结束的批次的跟踪。不联系服务端，不取消、不退款；如果其实已经受理，扣费照常生效。
- 不用 `--resume`、直接再运行**完全相同**的生成命令（描述、模型、风格、比例、张数、参考图都不变）时：
  - 上次同样的请求结果未知：用原来的请求 ID 重发（同样先确认价格，余额低也可以重发），不会另建一个请求。
  - 上次同样的请求已经受理、那一批还没结束：继续查看那一批，不会再扣费。那一批结束之后，同样的命令才会生成新的一批（重新扣费）。
- 参数有任何不同就是新请求；这时 CLI 会列出其它结果未知的请求 ID，提醒你先确认它们。
- 两个终端同时运行完全相同的命令时，只有一个会发出请求：另一个在发出前发现它，已受理就接着查看那一批，结果还没回来就停下并给出 `--resume` 命令，不会扣两次。`yomi persona avatar` 也一样。

## yomi video：动态封面与介绍视频

```bash
yomi video --options                                    # 模板、时长、展示价（不扣费，不需要 -f）
yomi video -f lin-xia.yaml                              # 自定义视频，默认时长，用作动态封面
yomi video -f lin-xia.yaml --prompt "她在窗边回头微笑" --duration <秒>
yomi video -f lin-xia.yaml --template <模板ID> --as intro-video
yomi video -f lin-xia.yaml --list                       # 这个角色文件的视频任务和已记下的结果
yomi video -f lin-xia.yaml --resume <请求ID>
```

视频是**为角色文件生成的**：结果按这个角色文件记在本机，`yomi create` 这个文件时随角色一起提交（见[视频怎样挂到角色上](#视频怎样挂到角色上)）。

选项：

- `--template ID`：模板（也可以写模板名称，只要只有一个模板叫这个名字）。不写就是自定义视频，`--prompt` 描述可写可不写，最多 2000 字。用模板时不能写 `--prompt`。
- `--duration 秒`：只能是这个模板（或自定义视频）允许的时长，默认用它的默认时长。
- `--frame 图片`：首帧，JPEG 或 PNG。不写时用角色文件的 `cover`，它必须是本地图片；`cover` 写成 `{ upload_id }` 或 `{ asset_id }` 时请用 `--frame`。首帧会居中裁成 9:16，缩放成 720×1280 的 JPEG。
- `--as dynamic-cover`（默认）或 `intro-video`：用作动态封面还是介绍视频。

流程：

1. 读视频配置（`ugc/video/config`），检查模板和时长，在本机准备好首帧。图片用不了就在这里停下。
2. 如果这个角色文件还有结果未知的视频请求，先列出它们的 `--resume` 命令。非交互运行时直接停下；在终端里继续的话，就是另一个新请求，会另外扣费，必须输入 `yes`（这时 `--accept-price` 不算数）。
3. 读余额，和配置里的展示价比较。余额不够就停下，不上传首帧，也不报价。生产环境在这里输入 `prod`。
4. 上传首帧（`ugc/video/frame/prepare`，私有上传，`ugc/video/frame/complete`），然后报价（`ugc/video/quote`）。这两步都不扣费。
5. 报价就是要扣的价格。报价和展示价不同时会提示；非交互运行时停下，因为 `--accept-price` 只同意和展示价相同的报价（配置里没有展示价时，同意的是报价）。显示报价和余额后输入 `yes`（或 `--accept-price`）。
6. 如果你考虑的时候报价过期了（按服务端的时钟算），CLI 会重新报价；价格变了要再确认一次。
7. 完整的请求存到本机后，发送 `ugc/video/create`。**这一步扣费**，同一个请求 ID 最多扣一次。
8. 每 2.5 秒查一次任务（`ugc/video/task`），最多 120 次，直到任务结束，而且扣费或退款都已经完成。
9. 成功：结果记在这个角色文件下，并下载预览视频（`ugc/video/media`）。失败或没通过内容检查：退款完成后显示「钻石已退回」，没有扣过费的显示「没有扣费」。`--json` 的 `refund` 字段：`refunded` 已退回，`refunding` 退款中，`not_started` 失败且已扣费、退款还没开始。

首帧图片必须是普通文件，最大 20 MB。

`--list`：列出服务端记录的这个角色文件的视频任务（最多 50 条，含状态和扣费），本机保存了、但服务端还没有确认的请求，以及已经记下的结果数量。

`--resume <请求ID>`（带上同一个 `-f`）：

- 已受理：继续查看。成功的会重新下载预览，不会再扣费。
- 结果未知：先问服务端有没有这个请求。有，就继续查看，没有重复扣费。服务端没有记录时，才显示价格和余额，确认后原样重发（同一个请求 ID 和请求体）。如果报价已经过期，服务端会拒绝且不扣费，重新运行生成即可。
- 本机没有这个请求的记录（例如请求是在别的电脑上发的）：只能按这个角色文件在本机的草稿去服务端查。查不到不代表没有扣费。

### 视频怎样挂到角色上

- 每次成功，结果按用途（动态封面或介绍视频）记在这个角色文件下。记录在本机，按角色文件的路径区分，同一账号、同一环境才有效；角色文件改名或移动后，就对不上之前的结果了。
- `yomi create -f 同一个文件` 时，提交的内容会带上这些视频：每个用途下所有成功的视频都在列表里，选用最新的一条，同时带上这个角色文件的草稿 ID。`create` 会显示「AI 视频：动态封面 N 条（选用最新一条）」，用 `--dry-run` 可以看到请求体。还没有成功的视频时，什么都不带。
- `yomi preview` **不带**视频，与 App 相同：预演只用文字、声音和图片。
- 视频要在 `create` 之前生成。已经创建的角色不会因此更新（CLI 还不能编辑已有角色）。
- 视频只跟第一个创建出来的角色走：一个视频绑定到一个角色后，不能再给别的角色用。所以之后再 `yomi create` 这个文件（加 `--new`，或改过内容）时，新角色不带这些视频；`yomi video` 也不会再为这个文件生成视频，而是提示视频已随哪个角色提交。要给新角色做视频，把文件复制成新的角色文件再运行 `yomi video`。
- 视频不影响「同一份内容已经创建过」的判断：只生成了视频、没改文件时，再 `yomi create` 仍会提示已经创建过。

## yomi persona：聊天人设与头像

`yomi persona list` 列出你的聊天人设（主控）：ID、名字、性别、年龄、头像（AI 生成 / 已设置 / 默认头像）、哪个是当前使用的、哪个是默认的，以及还能不能新建。加 `--json` 输出 JSON。如果本机还有没拿到最终结果的头像生成，会提示继续用的 `--resume` 命令。

```bash
yomi persona avatar --options                              # 模型、单价、风格、每次张数（不扣费）
yomi persona avatar -p "短发，戴眼镜，笑容温和"            # 选一张写进当前使用的人设
yomi persona avatar -p "…" --persona <人设ID> --pick 1     # 直接把第 1 张写进这个人设
yomi persona avatar -p "…" --new --name 阿遥 --gender female --age 24
yomi persona avatar --resume <请求ID> --pick 2
```

写进哪个人设。这在扣费前就会检查，不对就不发请求：

- `--persona ID`：已有的人设，ID 不存在就报错（`yomi persona list` 查看）。
- `--new --name 名字 --gender male|female|other --age 年龄`：用选中的图新建一个人设。名字 1–50 字，性别也认「男 / 女 / 其他」，年龄 18–150。人设数量到上限时报错。新人设不会自动设为默认或当前使用，可以在 App 里切换。一次生成最多新建一个人设。
- 都不写：当前使用的人设；没有当前使用的，就用默认人设。

其它选项：`-p` 描述，最多 500 字；`--model` 默认第一个，`--style` 默认不选；`--count` 默认是服务端的每次上限，不能超过它；`--reference` 参考图，JPEG 或 PNG，不超过 20 MB，居中裁成 3:4、缩到高度不超过 1024 px 后上传（同意价格之后才上传）。

流程：

1. 读头像配置（`user/get_conversation_persona_avatar_config`）和人设列表（`user/get_conversation_persona_list`）。没有可用的模型、或者读不懂价格时，不发请求。
2. 显示「单价 × 张数」和余额。这是全部成功时的总价；实际按成功的张数计费。输入 `yes`（或 `--accept-price`），生产环境再输入 `prod`。
3. 请求存到本机后，发送 `user/create_conversation_persona_avatar_task`。**这一步计费**：按成功的张数计，生成失败或没通过内容检查的那张不计费。如果服务端是先扣后退，退回的金额以钱包记录为准。
4. 每 2 秒查一次（`user/batch_get_conversation_persona_avatar_tasks`），最多 90 次（约 3 分钟）。Ctrl+C 只停止查看。
5. 下载成功的图片（原样保存，不裁剪），逐张显示结果，并按成功的张数汇总花费。服务端标为成功、却没有给出可用图片的那张，不能选用。
6. 选一张写进人设：
   - `--pick N`：直接写入第 N 张。
   - 不写 `--pick`、在终端里运行时，会问选第几张（直接回车跳过）。
   - 非交互运行或加了 `--json` 时，只下载不写入。之后用 `yomi persona avatar --resume <请求ID> --pick N` 写入，也可以再加 `--persona ID` 或 `--new …` 换一个目标。
   - 在生产环境写入人设前，如果这次运行还没有确认过，要输入 `prod`。

`--resume <请求ID>` 只能继续这台电脑上、这个账号发起的生成；`-p`、`--model`、`--style`、`--count`、`--reference` 这时不起作用。

- 已受理：只查看、下载、选图，不会再扣费。
- 结果未知：原样重发（同一个请求 ID 和请求体）。这个模型的单价比当时同意的高时，重新显示价格和余额并要求确认；没有涨价就直接重发（生产环境仍要输入 `prod`）。
- 重发被服务端拒绝（例如余额不足）时，这次重发没有扣费；但上次那次可能已经受理，所以本机记录和请求 ID 都保留，以后仍用同一个请求 ID 重发。先后以不同单价发出过的，按哪个价扣以钱包记录为准。
- 再次运行完全相同的生成命令时，如果同样的请求结果未知，CLI 不会发新请求，而是提示你用 `--resume`。
- `--new` 新建人设的结果未知时（网络中断等），本机会记下这次新建。下次写入前先查人设列表：已经建好就不再新建；列表里没有，要在终端里输入 `yes` 才会再建；非交互运行时，先用 `yomi persona list` 确认列表里没有，再加 `--create-again` 代替输入 `yes`。

## relay 的 /image

在 `yomi relay --telegram` 里给 bot 发 `/image`，会根据当前角色最近一条回复生成一张图片，好了以后作为图片发到 Telegram。回复角色的某条消息再发 `/image`，就根据那一条；还没有回复时，根据开场白。没有描述可写：图片由服务端根据对话生成。

- 一次只生成一张。正在等一条回复或上一张图片时，不能再发 `/image`。
- 价格：`/price` 会一起显示每张图片的价格。收费的必须先用 `/budget` 设好预算，而且不超过本机的 `--max-spend`。显示免费的图片（服务端的免费额度）不需要预算，但免费次数只是当时的快照（在别的设备上用掉后就按原价扣），所以它的原价也必须在本机 `--max-spend` 还能花的范围内；默认 `--max-spend 0` 时，开着计费的对话不会发起生图。服务端开着计费却没给价格时，按价格未知处理，不发起。不论收费与否，读不到余额都不会发起。第一次给某个角色付费生图前，会先显示单价和余额。
- 图片送达对话时才扣费。计入预算的是任务自己的扣费状态：已扣费按单价（显示免费却被扣了的，按原价并暂停 relay），没扣、已退款或扣费失败的不计；不看同期的余额变化，所以同时在别处花的钻石或充值不会算到这张图片上。
- 只转发这个 relay 自己发起的图片，不会转发你在别的设备上生成的图片。
- 结果未知时不会自动重发：`/image resume` 用同一个请求重发（不会重复扣费；余额低于单价也可以重发），`/image forget` 放弃追踪。重发被拒时，被拒的只是这次重发：上一次可能已经受理，所以请求和它待结算的花费都保留，可以稍后再 `/image resume`。放弃后，如果它其实已经受理，图片仍会出现在 Yomi 对话里，并在送达时扣费，这笔花费可能没有计入预算。已经受理的图片不能放弃追踪。
- 上一次生图的结果还不确定、图片还没送达，或者扣费还没结算完时，relay 不会发出新的消息或生图。收费图片送达后扣费还没到账的，从送达起最多再等 180 秒。
- `/stop` 只停止等待：服务端会继续生成，送达时照常扣费；`/image resume` 继续等待并转发。

relay 的配对、预算和其它命令见 [relay.md](relay.md)。

## 结果保存在哪里

`--out <目录>` 指定保存位置，默认是当前目录下的 `yomi-media/`，不存在时会创建。

| 命令                  | 文件                                                                                                                                              |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `yomi image`          | 原图 `yomi-image-<批次ID>-<N>.<png/jpg/webp>`；封面 `yomi-image-<批次ID>-<N>-cover.jpg`（1:2，720×1440）；头像 `…-<N>-avatar.jpg`（1:1，512×512） |
| `yomi video`          | 预览视频 `video-<请求ID>.mp4`（扩展名按服务端给的格式）                                                                                           |
| `yomi persona avatar` | `persona-avatar-<请求ID前 8 位>-<N>.<扩展名>`，原样保存                                                                                           |

- 封面和头像是从原图中心裁出、再缩放的 JPEG（质量 92），与 App 准备图片的方式相同。只能裁 JPEG 和 PNG 原图；WebP 或解码失败的原图只保留原图。
- 下载只用 https，不带登录凭证，不跟随重定向。图片最大 20 MiB，视频最大 100 MiB，服务端给出视频的大小和 SHA-256 时会校验。结果的临时地址不会打印，也不会保存。
- 同名文件会被覆盖，例如 `--resume` 重新下载的时候。
- relay 的 `/image` 不保存文件，图片直接发到 Telegram。

## 本机记录

请求 ID、冻结的请求体、批次和任务 ID、视频结果都记在配置目录（默认 `~/.config/yomi-cli`，或 `YOMI_CONFIG_DIR`）的 `state/` 下：按账号和环境分开，文件权限 0600，不含 token。多个 `yomi` 进程（例如后台运行的 relay 和另一个终端）可以同时使用，每次写入都加锁。删掉这些文件后，`--resume` 就找不回结果未知的请求，`yomi create` 也找不到之前生成的视频。

## 给脚本用

- 非交互运行时，要用 `--accept-price` 同意价格；连生产环境还要加 `--confirm-prod`。少了它们，命令不会扣费。
- 加 `--json` 时，标准输出只有一个 JSON 对象（结果、请求 ID、批次或任务 ID、价格、扣费与退款、下载的文件），给人看的提示写到标准错误。结果未知时为 `unknown`（`image` 和 `persona avatar` 看 `status`，`video` 看 `outcome`），并带着用来 `--resume` 的请求 ID。
- `--debug` 打印请求日志（凭证已脱敏）。
